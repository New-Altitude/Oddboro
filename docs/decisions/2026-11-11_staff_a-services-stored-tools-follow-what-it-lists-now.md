- [staff] **Decision (2026-11-11): a service's stored tools follow what it lists now: the office reads them on each run that uses it, as it starts, once a day while it runs, and on the owner's Refresh, and keeps the tool list, what Read only reaches (the same rule as connecting, both ways), and what each tool does.** Servers add, drop and remark tools, and a list stored once went stale: the Services page showed tools that were gone, Read only never gained a new read tool without reconnecting, and a dropped tool kept its standing yes, so a new tool by that name would have gone through without asking. Now a dropped tool leaves every standing yes, and each change but a description gets a Ledger line. Physical mail keeps the three reads the office picked at setup. The daily look is one timer, so a service no run uses still stays current. Like Claude Code, which lists a server's tools at each session's start, the live list wins; the office keeps a copy because its page has no open connection to read. Code in `packages/ledger/src/office-service-tools.ts` (`refreshTools`) and `apps/office/src/lib/server/access.ts` (`startToolRefresh`, `refreshService`).
