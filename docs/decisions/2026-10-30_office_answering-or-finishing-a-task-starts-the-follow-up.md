- [office] **Decision (2026-10-30): the owner answers an ask with Deny, Iterate or Approve. Approve and Iterate each start the staffer at once, and so does marking done a task a staffer gave them (an intake goes back to the staffer that sent it, which then proposes the hire), and the owner hears back only when it fails or needs them, unless they tick "Report when done" (off by default).** An answer is enough to get the work done, so the owner never has to check on it. Deny starts no work. Iterate needs their words, and the reworked ask comes back linked to the one they sent back. An ask the office raised itself, to keep work going past a round's hand-offs or the usage window, takes a yes or a no only, since no Odd could rework it. Every outcome goes in the ledger and in the Office Manager's daily report. A run cut off by a restart fails rather than run twice, because an approved action may have half happened. A failure that goes back to a thread's lead, cut off or not, goes to the lead only, since the lead picks it up at once; the owner's desk gets only a failure no lead is woken for (ruled 2026-11-04, after a failed hand-off reached the desk once its lead had handled it). Supersedes the 2026-10-30 ruling that only approvals start work. Finished tasks joined the ruling on 2026-10-31, after a finished intake brought no hire back. A task an Odd gives in a chat keeps the owner's message there, and the run its end starts reads it beside their note (ruled 2026-11-11, after a pick-up saved an answer to the wrong file because it never saw what the chat asked for). Code in `apps/office/src/lib/server/follow-ups.ts`.
