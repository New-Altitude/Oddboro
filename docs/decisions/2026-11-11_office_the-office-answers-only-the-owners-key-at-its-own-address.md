- [office] **Decision (2026-11-11): the office answers only at its own names (127.0.0.1, [::1], localhost, its addresses through Caddy and the app's ORIGIN), and only to a request that carries the owner's key, with exact exception routes that prove themselves another way.** Any program on the computer, and any page open in the owner's browser, can send the office a request with whatever headers it likes, so headers cannot tell the owner from anyone else. The office keeps one key in its folder (`owner-key`, made on first use). The owner's page holds it as the cookie `oddboro-owner-<port>` (SameSite Lax, named by the office's port, since a browser scopes cookies by host and not port), and gets it by opening any page once with `?oddboro-key=<key>`, which the office answers with a redirect to the same address and the cookie. The app's shell, `npm run setup` and the shell's new windows on the office's own origin open with it. Without the key a request, a read included, reaches only an exact exception route: `/api/update` with the shell's token, `/api/gateway/<id>` with a run's token, and GET or HEAD on the two sign-in callback pages with their own sign-in state. The path is judged on the text the server routes on and never decoded again. With the key, an action (anything but GET, HEAD or OPTIONS) must also come from the owner's own page, told apart by what the browser says (Sec-Fetch-Site, or with none an Origin naming the host asked), because a page on another localhost port is same-site and carries the cookie too. In dev, a first Vite plugin applies the same rule ahead of Vite's own routes and its websocket, and Vite's `/__open-in-editor` is refused outright. Limits: the key stops a program on this computer only when it cannot read `~/.oddboro` (an Odd behind its walls, a browser's pages, another user's programs); a program running as the owner can read the key, as it can read the database beside it. The key also appears once in `open`'s arguments and in the browser's history as the address before the redirect. Code in `packages/ledger/src/owner-key.ts`, `apps/office/src/lib/server/owner-page.ts` (`guardOffice`) and `apps/office/vite.config.ts` (`ownerOnly`, `noEditorLaunch`); supersedes the 2026-11-04 ruling.
