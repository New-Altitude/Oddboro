- [office] **Decision (2026-11-11): the office answers only this computer, only at its own names (127.0.0.1, [::1], localhost, its addresses through Caddy and the app's ORIGIN), and takes an action (anything but GET, HEAD or OPTIONS) only from the owner's own page, with one exception: the app's shell reports updates with the token it gave the server.** A request comes from this computer when the connection's address and every address in X-Forwarded-For are loopback. On a Mac and Linux Caddy listens on every address, and through it the connection is always from 127.0.0.1, so the address Caddy forwards for, which it writes itself, is what keeps another machine out; a program on this computer can still write that header. Other pages open in the owner's browser can send requests to the office too, and only the owner's own page may act in their name. SvelteKit's own check covers form posts only, so the office checks every route and API request itself, in every mode; the built server serves files built into the page before the check. Under `vite dev`, which setup and the login service run, the rule that the request comes from this computer also runs before Vite's own routes and its live-reload websocket, so they refuse another machine too. The page is told apart by what the browser says (Sec-Fetch-Site, or with none an Origin naming the host asked), since through Caddy the page is https and the office http. The names refuse a site that points its own name at this computer. Vite's dev server route `/__open-in-editor`, which opens a file in an editor and runs before that check, is refused outright, since nothing in the office uses it. Supersedes the 2026-11-04 ruling. Code in `apps/office/src/lib/server/owner-page.ts` (`guardOffice`), `apps/office/src/lib/server/this-computer.ts` (`fromThisComputer`) and `apps/office/vite.config.ts` (`onlyThisComputer`, `noEditorLaunch`).
