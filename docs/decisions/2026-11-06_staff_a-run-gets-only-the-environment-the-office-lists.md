- [staff] **Decision (2026-11-06): an Odd's run, on any AI tool, gets only the variables the office lists from its own environment, and the office's tool server gets each one it reads by name.** Before, a run got the office's whole environment less names matched by pattern, so any variable the office picked up (a token, a git setting, the app's update token) reached every Odd's tool. `RUN_ENV_ALLOW` in the office's `run-env-allow.ts` lists them, for every system, per system and per tool, each with the tool that needs it. Each tool's launch adds its own variables after `runEnv`, as before. The tool server's entry sets every name in `TOOL_SERVER_ENV` that the office has, so the server never depends on the AI tool passing it on. A sign-in, an install or a version check the owner starts keeps its own environment (`cleanEnv`, `vendorEnv`), since the owner's own tools may need what a run never should. An outside tool's own server, which the office's gateway now starts for a run instead of the run's tool, gets the names listed for every system and this one, none of any AI tool's (`outsideToolEnv`), so moving it into the office gave it no more than a run had. A folder stored for an Odd that is in or holds a secret store reaches no run on any tool, even one given before its store was listed (`touchesSecretStore` in the ledger's `office.ts`, the test the folder check makes). `launch-contract.test.ts` starts every tool on every system it runs on from an office whose environment holds things no run should get, and holds all of this.
