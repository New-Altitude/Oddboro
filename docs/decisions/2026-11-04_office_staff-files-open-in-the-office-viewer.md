- [office] **Decision (2026-11-04): files a staffer writes open in the office's own viewer, rendered or editable, and only files already inside that staffer's folder, its own part of a thread's folder, or a folder the owner gave it.** The owner reads and edits what the staff made without leaving the office, and the viewer cannot become a way to browse the Mac: a folder the owner gave is one the owner already chose. A bare file name the staffer's folder lacks opens the newest file of that name it wrote in a thread's folder, such as a goal's, and the owner sees only that bare name, since a thread's number and folder mean nothing to the owner. No link to a file or a folder is followed, and the viewer takes a bare name or a path inside the staffer's own folder whose real path stays inside it, never a full path, except into a folder the owner gave it. A full path naming a file in a thread's folder, in a staffer's text or a `file:` link, is a name, for the staffer whose part of the thread holds it: the page turns it into that file's name in the office, the viewer opens it through `workFile` while that staffer is on the thread, and it shows by its bare name. A full path into a folder the owner gave the staffer, in its text, code or a `file:` link, opens that one file, never through a link out, and shows by the folder's name and the path inside it (`site/index.html`). It opens only to read, since the owner's folder holds the owner's own work; a folder that shares its name with another one given, or a drive's top, names nothing. A `file:` link that names no office file stays text. The Storage tab shows a staffer's parts of its threads by each thread's title, never a thread's number or folder. A file a staffer attached from the folder of a thread it is on, such as a page a colleague built for a goal, opens as that one file, by its bare name and only to read, since the staffer that attached it may not have written it. A page a staffer built (`.html` or `.htm`) also gets an "Open in browser" button, in the viewer itself and beside its name in a staffer's text, that opens it as a file on the Mac, outside the office's address, found the same way and only from the owner's own page, since a page is easier to judge rendered than as source. The office never reads that page, so the viewer's size limit does not apply to it. A save never overwrites a change the staffer made after the owner opened the file. Code in `apps/office/src/lib/server/files.ts`, `apps/office/src/lib/server/storage.ts` and `apps/office/src/lib/ui/markdown.ts`. This supersedes the 2026-10-30 ruling, and this ruling's 2026-11-04 text that kept a thread's files out of full paths and the owner's given folders out of the viewer.
