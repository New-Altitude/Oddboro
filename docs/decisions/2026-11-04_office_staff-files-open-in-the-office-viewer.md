- [office] **Decision (2026-11-04): files a staffer writes open in the office's own viewer, rendered or editable, and only files already inside that staffer's folder or its own part of a thread's folder.** The owner reads and edits what the staff made without leaving the office, and the viewer cannot become a way to browse the Mac. A bare file name the staffer's folder lacks opens the newest file of that name it wrote in a thread's folder, such as a goal's, and the owner sees only that bare name, since threads and their folders are the office's plumbing. No link to a file or a folder is followed, and the viewer takes a bare name or a path inside the staffer's own folder whose real path stays inside it, never a full path. A file a staffer attached from the folder of a thread it is on, such as a page a colleague built for a goal, opens as that one file, by its bare name and only to read, since the staffer that attached it may not have written it. A page a staffer built (`.html` or `.htm`) also gets an "Open in browser" button, in the viewer itself and beside its name in a staffer's text, that opens it as a file on the Mac, outside the office's address, found the same way and only from the owner's own page, since a page is easier to judge rendered than as source. The office never reads that page, so the viewer's size limit does not apply to it. A save never overwrites a change the staffer made after the owner opened the file. Code in `apps/office/src/lib/server/files.ts`. This supersedes the 2026-10-30 ruling.
