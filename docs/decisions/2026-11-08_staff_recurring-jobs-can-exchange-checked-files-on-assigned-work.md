- [staff] **Decision (2026-11-08): recurring jobs can exchange a named result on work their Odds serve, and the office checks each period's file through its file tools.** Each job keeps its own timer, reads its assigned input and writes in its own part. A reader takes the file its writer's last run for a period at or before the reader's own period wrote, by that run, never by whether the bytes changed. A writer that ran for that period and left no checked file fails the reader's run. A writer still owing that period, as after the Mac slept, makes the reader wait and run after it, as does a writer whose catch-up waits for the owner's yes. A writer that skipped it, or whose catch-up the owner refused, makes the reader skip it quietly, on the While you were away card. Files that would make jobs wait on each other in a ring are refused when set. The owner can approve including named sources in that result without granting colleagues those sources. A parked thread still wakes only its lead. Code in the office's `scheduled-files.ts` and `jobs.ts`, and the ledger's `office.ts` (`scheduledInput`) and `files-server.ts`.
