# Work in a native project session

Project sessions need **Advanced mode**, which is off until you turn it on. While it is off, the office shows no Projects button and no **Project sessions** menu item, gives no Odd the project tools, and refuses every project request.

## Turn on Advanced mode

1. Click **Setup** under the office's name.
2. Under **Advanced**, click **Turn on**.
3. Read the warning: work sent to Claude Code or Codex runs with your permissions on this computer, outside Oddboro's limits, and can change files, run commands or reach the internet as your coding tool allows.
4. Click **Turn on advanced mode**. **Projects** appears in the top bar.

The ledger keeps your yes, with the date and the warning's words. Turning it off is a ledger line too. It takes every Odd off every session and stops project work still waiting. Open terminal views close. Work already running in Claude Code or Codex keeps running there, and the conversations stay in the native tool.

## Open Projects

Open **Projects** in the office's top bar, or **Project sessions** from the plus menu beside an Odd's chat box. Projects opens as a tab in the side panel, which widens to the Odd's chat, or to the Odds while no chat is open. Drag its edge to make it narrower; the office remembers that width for Projects alone. Hovering the Odds narrows it so you can pick one. The music player stays where it is, except under **Focus** (below). The tab's ✕ closes Projects; sessions keep running.

- Every session is listed down the start side: the tool's mark, the project folder's name, the conversation title under it, and a dot for its state (sea for working, ember for waiting for you, moss for done, grey for idle). A portrait shows the Odd allowed to send work there, ringed in ember when it may send without asking. Up and Down move between sessions; Enter opens one.
- The selected session fills the rest: a slim header (folder, tool, the conversation ID to copy, **Take control of terminal**, **Details**, **Disconnect**, and **Stop** on a connected Claude session) and the native terminal under it, which fills the space and refits once the panel stops changing size.
- **Details** folds out over the terminal: the instruction or correction box, Codex's questions, the Odd allowed to send work, **Let <Odd> send work without asking**, and every request with its state. A count on **Details** says how many wait for you.

The office opens the Codex or Claude Code installed on this computer. The native client reads its usual account, project instructions, skills, hooks and tool settings. A Claude Code session runs in one Claude folder, the one it was started or found in: `~/.claude`, or a folder you named in Setup under Advanced (see below). A session connected before sessions kept a folder runs in the office's own default folder: the one the office's `CLAUDE_CONFIG_DIR` names, else `~/.claude`. A worktree is a separate project. The session identifies the project by its full path and the conversation by its native ID.

## Start or connect

1. Click **+ New session** at the top of the list. Choose the project folder, by its full path or one starting with `~`, and the coding tool. Then answer **What would you like to do?** with **Start a new conversation** or **Continue an earlier one**. Switching between the two keeps what you typed. To start, give the session a name if you like, and select **Start**. For Claude Code, with more than one Claude folder known, the start also asks for the **Account**, the Claude folder it starts in; it starts as `~/.claude`.
   A Claude conversation the office starts or reopens runs in Claude Code's background service, and the terminal in Projects attaches to it. So a terminal anywhere can join the same conversation live: run `claude --resume <id>` in the project folder with the session's Claude folder, which **Details** shows, and both windows show the same typing, with one conversation ID and no copy. Claude Code draws a session for the window that resized it last, so in two windows of different widths the other one shows text laid out for the wrong width. Clicking into the office's terminal draws it again for that window, by making it one column wider for a moment, and so does resizing a window. For a Claude folder other than `~/.claude`, run `CLAUDE_CONFIG_DIR=<folder> claude --resume <id>`. Another Claude folder does not find the conversation, or opens a different copy of it. Claude Code 2.1.285 or newer is needed; an older one is refused with "Update Claude Code to use Projects: run claude update". Codex sessions run as before.
   In a folder this Claude folder was never told to trust, **Start** opens a small terminal under the form with Claude Code's own question, under the line "Claude Code asks once before it works in a new folder. Answer its question there, and the session starts." Answer it there; the terminal closes and the session starts. If Claude Code was not told to trust the folder, nothing starts and the form says so: "Claude Code was not told to trust this folder, so nothing started. Choose Start to be asked again." The terminal also closes when you change the folder, tool or account, leave the form, or close the Projects window. It also closes, and the form goes back to **Start**, when another Projects window starts a session in the same folder and account; nothing starts in the first window, and its form says "Another Projects window started a session in this folder, so this question closed." until you choose **Start**.
2. **Continue an earlier one** lists the folder's conversations at once, from every Claude folder, each with its title, Claude folder, activity time and ID. Type in the filter box above them to narrow the list by title, account (Claude folder or login) or the start of the ID; it searches only the list already shown. Select one to open it. The list loads again by itself when you change the folder (choose another, or type one and leave the field) or the tool; typing alone does not. Without a folder, it asks you to choose one. **Refresh list**, at the end of the filter row, lists them again.
3. For Codex work still running on a separate App Server, enter its private Unix socket under **Connect to a running Codex server** before you choose **Continue an earlier one**, or choose **Refresh list** after. Use the socket the original client connected to. The socket's parent directory must be private to your account. For example, a server launched with `codex app-server --listen unix:///path/to/private/codex.sock` and a terminal launched with `codex --remote unix:///path/to/private/codex.sock` share that server. The office can join a turn in progress there. On a client that keeps its server private, finish or interrupt the turn and **close the original client**. Select **Hand over this conversation** in Projects. The office resumes its saved ID.
4. A Claude Code conversation that is open the normal way in a terminal shows in the list as **Running in a terminal**. Two plain Claude processes on one conversation would copy it, so the office does not attach to it as it is. Select **Move here** beside that entry, then confirm under it. The office checks that Claude is at its prompt with nothing still working, and checks again just before it ends the terminal's process gently. It then continues the same conversation in the background under the same ID, and attaches. The conversation is kept, and it is not copied. When that terminal used a Claude folder other than the session's (for a session with none, the office's default folder), the session continues and stays in the terminal's folder, and says so above the terminal. A reply that starts in the moment between that last check and the end is cut short. If the terminal is still closing 5 seconds later, the office says so: wait a moment, then try again. If that terminal is no longer showing the conversation when the office checks again, because another one is open there or it is closing, the office closes nothing and says so: try again. If Claude is still working in that terminal, or is waiting for your answer there, the office says so and moves nothing: finish there, then try again. To keep using it in that terminal too, run the command the terminal shows. On Windows there is no **Move here**: in that terminal, type `/exit`, then select it here again. To give this existing session office assignments, follow the plugin commands under **Details**. A fresh session or saved conversation launched by the office loads the plugin for that launch.
5. Choose **Open terminal** to use native commands, respond to the provider's prompts and work with files. For an office instruction, open **Details** and enter a project-relative filename under **Project file**. Codex receives supported images as native image inputs. Claude reads the file in the selected project. Keep your usual project permissions. A first visit to a folder with Codex can present the provider's normal trust question. For Claude, the setup terminal under **Start** asks it (see Start or connect, above).

- **Continue an earlier one** moves a Claude Code session to the Claude folder of the copy you pick. If that folder no longer holds the conversation and another one does (for a session with no folder, the office's default folder counts too), the pick is refused: choose **Refresh list** to see where it is now. **Reconnect** moves one whose folder lost the conversation to the folder with its newest copy, and says so above the terminal, naming the folder it left by its path.
- **Reconnect** tells you, above the terminal, when another Claude folder holds a newer copy. The session still opens its own.
- **Focus**, at the end of a connected session's header, folds away the office's header, the window tabs, the **Projects** title row, the session list and the music bar, so the terminal fills the panel's height. Press it again to bring them back. The office remembers the choice on this computer, and it starts off. With no session open, or a session that is not connected, the title row and list always show, so **+ New session** stays in reach.
- In a narrow window, the session list stacks above the form as a strip, and the body scrolls. At every width down to 340 px, the Projects window stays clear of the Odds rail.
- An error shows beside what caused it, so a long list never hides it. On the New session form: a folder **Choose folder** could not pick shows under the folder, a start under **Start**, a conversation that would not open directly under its row, and listing the conversations or handing one over above the conversations found. Typing in the filter clears an error under a row. An error reading the sessions shows at the top of the form. With a session open, every error shows over its terminal.

One office terminal view accepts typing at a time. The window where you connect, reconnect or open the terminal takes it. **Take control of terminal** transfers input to another view. Closing Projects detaches the view. **Disconnect** releases the office connection after current work finishes. It closes the office's view only: the Claude session keeps running for any other window joined to it, and Claude Code frees it after about an hour with no window open. **Stop**, in a connected Claude session's header, ends the session for every window joined to it, after a confirm. The conversation is kept, and the session can be opened again from the list. If you type `/exit` in the office's terminal, Claude Code opens its agent view there; press Esc to close it, and the office shows its usual closed-terminal state. **Remove**, beside **Reconnect** on a disconnected session, takes it off the list. It also stops the session's Claude background job, ending it for any window still joined. It does not delete anything: the session and its requests stay, so connecting the same conversation again shows it back with its history. Remove also stops sharing it with an Odd and stops its waiting requests, your own queued ones included. Until it is connected again, sharing it, letting an Odd send it work without asking, or sending it work is refused with "This session was removed from Projects." To pick the work up outside the office, resume the displayed conversation ID from its project folder, or, while its Claude background job still runs, run `claude attach <short id>`. Close the prior writer before a saved-session handover. The office never asks the provider to fork to resolve contention.

## What it costs to run

Claude Code's background service is the only way Claude Code offers to join one conversation from two windows without copying it, and it uses memory while any session runs. Measured on a Mac with `ps` (resident memory, one Claude folder):

- A terminal session today: one process, 344 MB.
- A background session: 331 to 345 MB, plus its terminal host, 63 to 81 MB.
- The office's attached view: 115 MB.
- The service itself, while any session runs, per Claude folder: 151 to 152 MB, plus a spare of 80 MB and 119 MB. It exits when no session runs.

## Give an Odd work

1. Open the intended session, then **Details**. Under **Odd allowed to send work**, choose the Odd. This gives that Odd access to a native session with your project's tools and settings. Choose **Only me** to revoke the grant.
2. In the Odd's chat, describe the project work you want. The Odd sees the sessions shared with it. It can read its request status and send an assignment. It cannot type in the terminal, approve a command or grant itself access.
3. At Read, the Odd can look up its assignments. At Draft or Act, the proposed instruction appears on the Desk and opens the exact session. **Take over and send** runs the displayed instruction as you, with the permissions already configured in your native session. The office checks the Odd's current access again before sending.
4. To let that Odd send without asking, tick **Let <Odd> send work without asking** and confirm the second warning. Only the Odd the session is shared with can have it, and only while it is at Act. Choosing another Odd, or **Only me**, clears it.
5. Open Projects to see the answer. Results include any file references returned by the native tool. An Odd's result also reaches its Desk report. Work assigned from an office thread queues a pickup on that same thread. Revocation cancels waiting work. Inspect an assignment that already reached the provider before stopping it.

During a Codex turn, **Send correction** steers that turn. **Stop** targets the turn shown when you clicked. A resolved permission request cannot authorize a later one. With Claude, a correction waits for the paired plugin to read it. The office distinguishes a pending correction from one Claude received. For a Claude interrupt, check the terminal before clearing the request. The owner can also speak directly in either terminal.

## If delivery is unclear

Before sending to Claude, the office checks that both parts of its paired
plugin answer a fresh probe. If either is missing, the assignment fails
without being sent. Under **Details**, connect the plugin in that conversation
and reload it, then choose **Retry** on the saved assignment. An installed
older plugin may need an update through `/plugin` first.

An offered assignment that Claude has not taken within a minute becomes
uncertain. The office does not resend it. A late answer can still finish it.

The office saves the instruction before submitting it. A connection failure after submission can leave a tool action complete even though the office missed its reply. Reconnect, inspect the native history and project files, then clear the uncertain request. Sending a new instruction is a separate action. If Claude is waiting to take an assignment, open its terminal to see trust, sign-in, permission or plugin messages. Managed installations must permit the plugin and its monitor. An attached background job belongs to Claude and can outlive the office.

## Exercise a change

Run `npm test -w @oddboro/ledger`, `npm test -w @oddboro/office`, `npm run check-types` and `npm run lint` from the checkout using Node 24 or later. The project-session ledger tests use a disposable database. They exercise competing claims, changed grants, repeated replies and delivery to a thread.

For a native test, run a separate office on an unused office port (on Windows, an unused database port too) with a temporary office home. Use a disposable project and signed-in clients. Keep a second conversation open in the same folder. Give the first conversation a unique fact, ask an Odd to use a project-only file, correct the assignment, then inspect the reply in both the office and the original client. Compare the full native IDs. Confirm that the second conversation received nothing. Repeat with permission denial, a stopped turn, an office restart and a revoked Odd.

The desktop terminal check uses the same launcher as the office. On Windows, `packages/ledger/src/project-terminal.ts` uses the bundled console and releases the input pipe and output worker after the child exits. Keep `node-pty` pinned until the [upstream cleanup issue](https://github.com/microsoft/node-pty/issues/965) is fixed and the check passes without the workaround.

On a release machine, stage the desktop with the repository's smoke test. Open both terminals in the installed application, enter and resize text and exercise a native permission prompt. Windows Claude plugin monitors require Git Bash. Test a managed machine with the plugin disabled as well as a machine where it is allowed.

To run the two-provider read and resume check yourself, open the disposable office first. Pass its loopback URL and an existing disposable project folder to the script below. It creates one uniquely named fixture, asks each provider to return the value in it, verifies the original conversation IDs and removes the fixture. The native clients retain their test conversations. Open the matching Projects entry if a provider asks for permission.

```sh
node apps/office/scripts/check-live-projects.ts http://127.0.0.1:4951 /absolute/path/to/test-project
```

## Current queue integration

Migration 0027 adds the two tables after scheduled file exchange (0026). Migration 0028 adds `owner.advanced_at` (Advanced mode, null while off) and `project_sessions.sends_unasked` (the one Odd that may send without asking). Migration 0036 adds `project_sessions.hidden_at` (set by Remove, cleared when the conversation is connected again) and `project_sessions.config_dir` (the Claude folder the session runs in; null for Codex, and for a Claude session not connected since the column came).

**Claude folders.** `~/.claude` is always known. The owner names others in Setup under Advanced (the `ODDBORO_CLAUDE_FOLDERS` key of the office's env file, kept as the owner typed each path, not its real path, because Claude Code names its Keychain sign-in after the path it is given). Setup also reads the home folder's top level and offers, as one-click adds, each folder there whose name starts with `.claude` in any case and that holds both `projects` and `history.jsonl`, and that is not known yet. It reads folder entries only: it never runs `claude` there, since `claude auth status` writes into the folder it reads, and never writes. An added suggestion is kept as the path `~/<name>` expands to, the same as typing it. It runs Claude Code only in a known folder that exists, or in the office's own default folder for a session with no folder (below), and for `~/.claude` it leaves `CLAUDE_CONFIG_DIR` unset, never set to `~/.claude`. A session remembers its folder (`config_dir`) and runs there. One with none runs in the office's default folder, read each time it opens, and is refused when that folder is gone; Reconnect looks for it there first and, found there, leaves it with no folder. Being that folder does not make it known: the New session form's Account and the Odds' deny lists hold only known folders, and Setup suggests it only when it is an account folder at the home folder's top level, as it suggests any such folder. If the owner takes a session's folder out of Setup, opening the session or its terminal is refused, and no `claude` command runs. A folder is shown as its folder name plus the email it is signed in as now. No Odd reads any of these folders.

The **Continue an earlier one** list for Claude Code reads Claude Code's own session files, `projects/<project key>/<id>.jsonl`, in each known Claude folder (`claude-sessions.ts`, `claude-project.ts`), and asks each folder's `claude agents` for running ones. A missing folder is skipped. A named folder whose `claude agents` call fails is left out and logged, so one bad folder never fails the list. A conversation saved in two folders shows the newest. It reads each file's two ends for the title, folder and last change, as the Agent SDK's `listSessions` did, without the SDK. The terminal library, `node-pty`, is an optional dependency that loads only when a terminal opens. When it is missing, `npm install` still succeeds and the terminal says it cannot open.
Session and request changes use `LIVE_TABLES`. Project
tools are declared in `OFFICE_TOOLS` and appear only for a shared conversation.
A run uses the shared `CEILING` to remain at Draft or Read. `nativeProjectEnv`
in `run-env-allow.ts` keeps native provider settings separate from office
credentials. Terminal input and output stay outside diagnostics.

Database and tool-server tests cover duplicate assignments and callbacks,
revocation, a run at Draft or Read, unchanged native IDs, and a result arriving
after its office work ended. The earlier authenticated checks above predate
this integration; the release checks still apply to the merged build.
